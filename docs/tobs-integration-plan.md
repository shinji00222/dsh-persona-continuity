# Tobs 与人格续忆项目规划

## 首版交付

以现有 `dsh-persona-continuity` 为实现仓库，优先接入 Windows 上 DSH 的 Tobs Bot 模式。用户创建及编辑人格，每个人格自行决定保存、合并、修正或跳过哪些长期记忆。用户能查看来源、修改、删除及按人格关掉自动整理。发布包移除问卷模拟的入口、API 和执行模块，开发中保留现有用户数据和旧版本回退路径。源码证据见[技术调研](tobs-integration-research.md)。

首版演示采用两个真实 Bot。让研究搭档和代码导师参与同一段讨论，各自记有用的事。重启 DSH，新开聊天，检查两者使用各自的记忆。在后续聊天更改一条项目决定，运行后台整理，再开新对话检查能否采用新决定并给出来源。普通 DSH 聊天照常运行。

## 开工约定

- Bot 接入层用宿主提供的会话归属找到 Bot，再映射到一个稳定的本地 `personaId`。按 ID 读写，显示名可以改，同名新建是另一份记忆。独立插件路径由任务 A 验证，B/C/D 可使用本地绑定或测试替身先开工。
- 长期记忆的唯一正文来源是 `$DSH_HOME/persona-continuity/memories/<personaId>/`。目录内放 `MEMORY.md` 短索引和 `notes/<noteId>.md`。每条笔记含标题、摘要、正文、更新时间、可选项目范围及来源会话和轮次。`MEMORY.md` 由笔记重建。人格配置、会话绑定、队列继续用已有 SQLite。目录无需 Git。
- 由宿主构造每轮身份和项目范围，模型只能选择条目和变更。按人格分目录，先检查会话归属，再按项目和查询选取有预算的短索引和相关详情。历史原文沿用受控读取。普通会话、子会话及无痕会话跳过记忆流程。
- 成功轮次提供有限对话和当前人格设定给后台模型。模型可返回空结果或提出新增和更新。后台回顾限定当前人格的可访问来源，优先核对冲突和重复笔记。首版用受控任务触发回顾，频率与成本实测后再决定持续调度方式。
- 文件库由宿主统一写入。按人格串行，允许人工与后台基于 revision 检测冲突。单文件用同目录临时文件和替换写入，索引可以重建。重试用稳定任务键和稳定条目 ID，确保写完笔记但来不及确认任务时可重放。用户在管理页明确删除的条目需要留最小删除标记，避免同一历史任务重放时复活。
- SQLite v4 旧记忆先在隔离 profile 做单向导入验证。保留原库与旧模拟数据。按既有 `personaId`、条目 ID 和时间保留归属，重复运行只补缺失条目，避免覆盖用户后来改过的文件。首次试用前核对数量、来源和重启后检索。

## Agent 并行任务

在各 Agent 开工前，集成负责人固定实现分支的共同基线，核对哪些现有本地修改要带入。调研时工作区 `README.md`、`client.js`、`cordis.patch.yml`、`index.js`、`lib/web.js`、`package.json`、`test/binding.test.js` 有已有改动。不要代替用户重置、暂存或覆盖。各任务用独立工作区或分支，共享入口最后由集成负责人接线。

| 任务 | 可立即开工的交付 | 独占范围 | 完成判据 |
| --- | --- | --- | --- |
| A · Tobs/DSH 接入验证 | 从 Tobs v1.7.0 开始，在隔离 Windows profile 固定实际安装的 Tobs/DSH 版本。验证 `botharness` 注入、Session Ownership、已有角色与 Bot 的 ID 映射、模型首请求和轮次来源。查清如何让 Git 存储退出实际读写。 | `spikes/tobs/` 和自己的验证记录。先不要改公共入口。 | 交付最小复现和请求样本。通过时给出已实测的接线方式；失败时指出卡在宿主服务、回合时序还是 Git，并列出需要改的准确路径。 |
| B · 本地文件记忆 | 实现人格目录、笔记读写、短索引、按项目和相关性检索、冲突检测及旧库导入。 | `lib/local-memory/`、`test/local-memory.test.js`。旧 `Store` 由集成负责人接线。 | A/B 隔离、改名、重启、重复导入、并发编辑、写入中断、索引重建和 Windows 路径边界的测试通过。 |
| C · 人格自主记忆与回顾 | 从现有提炼和历史读取中复用输入裁剪、模型 JSON 调用和证据校验。让人格按自身目标决定写入，再输出有证据、可重试的更新。用文件库替身验证。 | `lib/memory-lifecycle/` 和 `test/memory-lifecycle.test.js`。可复用 `lib/extract.js` 与 `lib/history.js` 的导出，共享入口由集成负责人改。 | 同一输入可由不同人格提炼出不同主题。能跳过无用信息，回看来源能修正旧决定，失败不影响聊天，重试不会重复写入。 |
| D · 界面与移除模拟 | 保留人格选择、编辑和记忆管理，增加自动记忆开关及来源展示。移除模拟 UI、路由和包入口，用替身验证记忆 API。 | `client.js`、`lib/web.js`、`locale/`、`package.json`、`README.md`、模拟专有模块和测试。`index.js` 中的模拟调度由集成负责人拆除。 | 设置和普通聊天入口正常。打包清单、路由注册和 UI 都没有模拟功能与用户资料。旧 profile 数据仍可由旧版本读取。 |

用 4 个 Agent 分别领 A/B/C/D。只有 3 个时，先开 A/B/C，集成负责人在 A 有结论后接 D。A 与 B/C/D 只共享下面的契约。A 的最终结果决定接入方案，其他工作无需等待 Tobs 结论。

## 共用接口约定

方法名为实施约定，模块各自提供测试替身，集成时由同一人接线。

| 职责 | 输入和输出 |
| --- | --- |
| 宿主解析身份 | `resolvePersona(sessionId)` → `{ personaId, workspaceKey, role }` 或空。Tobs 层只接受宿主的所有权数据。 |
| 文件读取 | `catalog(scope, query, budget)` → 短索引，`readNote(scope, noteId)` → 正文、来源和 revision。`scope` 由宿主构造。 |
| 文件更新 | `upsertNote(scope, note, { operationId, expectedRevision })` 和 `deleteNote(...)` → 已应用、重复或冲突。模型输入里的人格 ID、绝对路径和会话归属都不能决定实际读写目录。 |
| 后台判断 | `{ persona, scope, sourceTurns, knownNotes }` → `[]` 或若干新增和更新意图，每项带来源。宿主验证正文、来源及 revision 后执行。 |
| 管理接口 | 延续现有已鉴权的人格和记忆列表、编辑与删除路由；增加自动记忆开关、来源 ID 和 revision。D 用替身先做界面。 |

## 合流顺序与验收

1. **验证 Tobs 接入。** 如果独立插件能拿到身份并完全接管长期记忆，采用独立插件。否则由负责人用 A 的证据决定维护最小 Tobs 补丁，或者先交付 DSH 人格续忆。两种实现都共享本地文件和后台模块。所谓接入成功，要实测 Tobs 新建 Bot 的长期记忆目录无 `.git`，且原有 Git 读写链路已退出。
2. **接上核心路径。** 由一人修改 `index.js`、`lib/store.js`、`cordis.patch.yml` 和原有集成测试，整合 B/C/D，卸下模拟调度。跑 `npm run check`、`npm test`。对旧 profile 副本验证迁移和重启，再跑 `npm pack --dry-run`。
3. **验证实际请求。** 用记录型假模型给两个 Bot 各造一条唯一测试事实。对照首次相关请求、低相关请求、普通会话、另一个 Bot、重启后新会话、人工编辑和忘记后，再核对文件状态及是否出现重复注入。失败样本与请求记录脱敏。
4. **试用。** 在隔离 Windows 桌面用目标模型完成两个 Bot、跨会话和纠错演示，检查答复能指出来源。记录 DSH、Tobs 和插件版本，说明迁移与回退路径。安装到日常使用的 profile、推送和发布分别确认。
